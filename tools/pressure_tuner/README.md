# J-Link RTT 压力实时调参

启动 `start.cmd`（Windows）或 `bash start.command`。脚本准备 Electron 和 Python 虚拟环境，依赖固定为 pylink-square 1.7.0。

主机必须用本仓库 **Tuning** 构建，屏幕必须配套更新。生产 Debug/Release 禁用 RTT 调参。默认表在 `firmware/main/Bsp/Src/pressure_tuning.c`。

1. 停止治疗，构建并烧录主机 Tuning，关闭其他 VS Code/J-Link 会话。工具内烧录按钮只更新主机，不更新屏幕。
2. 目标保持运行，点击连接。连接不主动停机、不复位、不依赖ELF变量名。
3. 选择档位、读取参数，修改四字段后应用。成功应答后才提示已应用；当前档在下一次压力控制计算使用。
4. “恢复默认并断开”恢复全部编译默认值。拔探针、杀程序、失去心跳后固件约2 s租约到期恢复。

| 字段 | 范围 | 含义 |
| --- | --- | --- |
| 前进速度上限 | 大于0、至65535 | 驱动单位，不是mm/s |
| 回退速度上限 | 大于0、至65535 | 回退及反向补偿 |
| Kp | 大于0、至1000 | 压差到速度的比例增益 |
| 减速比例 | 0.01～1 | 减速区间相对目标压力的比例 |

使用RTT消息由MCU更新临时参数，不存EEPROM/Flash，不周期读取压力曲线。RTT通信缓冲区和临时参数本身位于运行RAM；没有GDB按变量地址直接改写的操作。退出恢复由固件租约实现，不依赖上位机退出回调一定执行。

连接故障先检查Tuning镜像、目标是否运行、探针是否被占用。多探针场景目前用J-Link默认选择，无探针选择界面。Windows自动查STM32Cube的JLink_x64.dll，也支持 `JLINK_DLL` 指定。

窗口及桥接自动测试已完成，RTT实机通信和恢复仍需按[台架验收](../../docs/台架验收.md)验证。
