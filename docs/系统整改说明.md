# 系统整改说明（2026-11-02）

## 基线与结论

原主机基线 `0e5bae49ca39e72bba283904f85c6080504ae801`，原屏幕基线见 `refs/archive/screen-baseline`；两份原目录未修改。联合仓库在 `software/9C-HTP100-System`，分支 `integration/system-reliability`，原始联合基线为 `baseline/imported`。

启动/停止不同步存在明确的软件结构缺陷：两端各自维护治疗状态，屏幕还自行倒计时，状态依赖一次性事件推动；丢掉或漏处理关键事件后，普通压力、温度、电量仍能更新，却不能自动纠正页面。这与现场症状相符。未采集本次现场 UART 波形，不能断言概率故障的唯一触发点就是某个字节丢失或某个回调。

此次消除了对单次事件的依赖：治疗状态与剩余时间由主机持有，屏幕根据持续状态快照重建显示。按键消抖保留，但增加消抖不能代替两端状态同步。

## 保留的产品行为

- 原五档四参数及默认数值保留：前进速度上限、回退速度上限、Kp、减速比例；速度单位仍为驱动单位，不是mm/s。
- 首次进入目标±10 mmHg即启动1 s保压计时，不要求连续在范围内满1 s。
- 每轮前进5 s未到范围则回退；压力低于50 mmHg后下一轮；整个治疗由主机总时长限制。
- 普通低电量在治疗中不自动关机，非治疗状态沿用原关机逻辑；物理断电不能由软件保证续疗。
- TMP112通信报警确认仍为1500 ms，但失败确认期间已关加热。压力采样/诊断故障保留原重试，输出先禁用。
- 普通语言/音效/版本等配置同步保留旧帧；治疗和预设保存改用新帧。参考归位、耗材、电源器件的电气协议未重做。

## 配置迁移与回退

主EEPROM采用0x80、0xB0两个41字节日志记录，覆盖17个已有U16配置/计数键。首次无有效日志时导入旧地址；提交失败保留上一完整记录，CRC错误记录无效。

新修改写入日志区，不同步旧固件原地址。回退旧固件可能看到升级前的参数/计数，因此升级前须记录；不能认为旧固件能读取新日志里的最新修改。两份日志都失效时尝试旧格式导入，不等于永久数据备份。

配对构建结果与哈希以最终`out`目录为准。实机步骤见[台架验收](台架验收.md)。本次未连接、下载或运行实物，云端CI未运行。

仍需台架确认真实UI、串口时序、不同负载超调、RTT后台访问、GPIO关断/IWDG、真实EEPROM掉电和参考端可靠性。之前GND断路同时损坏测温与硬件保护，软件不能修复这种硬件共同故障，必须验证板上独立关断能力。
